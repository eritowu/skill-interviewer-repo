# 速成模式

適用：低風險、個人流程、決策點少、產物先給本人用。目標約 6 到 9 個高價值問題、十五分鐘內。產物版次標 `v0.1（coverage limited）`。

## 提問順序

依「對正確性的預期影響」選下一題，不機械照表推進。一題答案覆蓋多格就多格勾銷，不逐格硬問：

1. **代表性正常案例**：「挑一次最典型的，從頭到尾怎麼做？」問到正常流程清楚為止。答案拆進空格清單，逐格落判例卡。
2. **失敗、退回、不對勁的案例**：「講一次做壞的、被退的、或你事後覺得怪怪的。」負面案例的資訊量大於正面——隱性判準多半藏在這裡。
3. **最高風險邊界（保底例外探測，不可省）**：從 question-bank 的對抗模板挑一個最切題的丟出去。速成推薦三選一：門檻邊界、對象抽換、最壞情況。
4. **輸出與驗收**：「最小可接受的成果長什麼樣？什麼會讓你直接打回票？」
5. **工具與依賴**：僅在流程明顯依賴特定工具、檔案、權限時才問。

停止條件：所有高影響未知都已 `confirmed`，或已明確標 `open`。

## 保底（不可砍）

速成再快，三樣東西必須存在，否則產物只是一份看起來完整的殼：

- 至少一張判例卡進產出。
- 至少一輪例外探測（上面第 3 題）。
- 需請示區必須存在——哪怕內容是「無：本流程專家授權全自動處理」。

## 快檢

速成模式可省略快檢。省略時：

- 在產出 skill 的 coverage 區標 `#未驗證`。
- 隨附的兩題測試 prompt（正常＋邊界）必須完整——那是使用者的自驗路徑。

## 升級為深度模式

觸發：任一硬訊號出現——挖出不可逆後果、產物要給本人以外的人用、出現第二位專家。明講建議升級，由使用者決定。

升級映射（同一套資料模型，**不重問任何已答的**）：

| 速成已收 | 深度中的位置 |
|---|---|
| 正常案例的判例卡 | 深挖段第一批決策點素材 |
| 失敗案例 | 例外候選，進對抗段驗證 |
| 空格清單 | 續填，不重建 |
| 台帳 | 原封沿用，確定度標記不變 |

升級後載入 `references/mode-deep.md`，從空格清單的未填格接續。
