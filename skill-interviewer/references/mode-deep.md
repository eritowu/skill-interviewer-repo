# 深度模式

適用：組織知識、高事故成本、多位專家或多決策點。產物目標是可供正式審核的完整草稿。三段接在地圖之後：深挖 → 對抗 → 收斂。

## 深挖（主體，逐決策點進行）

對空格清單上的每個決策點，問到三樣東西：

- **判準**：看什麼？
- **門檻**：多少算過、多少不行？
- **理由**：為什麼是這個門檻？門檻背後常有一次事故——挖到事故就是挖到根，而且專家講事故不會給合規作文。

做事型與混合型的決策點加問兩樣（模板見 question-bank 深挖第 9、10 條）：

- **順序依賴**：這步之前必須先發生什麼？什麼證據證明它完成了？
- **輸入缺失**：該有的資訊拿不到時——繼續、假設、還是停下請示？

追問模板在 question-bank。每個有內容的回答落判例卡、記台帳。

## 對抗（每個決策點至少一輪）

例外幾乎只會在這段出土——專家自由陳述時根本不會想起它們。從 question-bank 的對抗模板選用，一次丟一個**具體**情境（帶數字、帶角色），不丟抽象假設。

- 專家答出「那種情況要…」＝挖到例外。**立刻回深挖**補這條例外的判準與理由，補完再丟下一個情境。
- 每挖到一條例外，接著問頻率與後果：「一年幾次？判錯最壞會怎樣？多久會被發現？」罕見且可逆 → 標記「問人即可」；罕見但不可逆或高代價 → 當場展開全套判準，編譯時升級為整份 skill 最硬的規則。
- 多位專家對同一情境給出相反裁決 → 開衝突條目：雙方立場、來源、完整原話全記台帳（私有），**不當場仲裁、不勸和**。衝突是要呈給組織看的訊號，不是要修掉的 bug。
- 停手訊號：同一決策點連續兩個對抗情境都沒挖到新東西 → 收工換格。挖乾的井繼續打，只會拿到現編的答案。

## 收斂

逐決策點**口頭重述**判準、門檻、例外，讓專家聽——他會在聽的過程中自然修正，每個修正都是新判例，落卡。重述完成後產出精簡藍圖（規格見 router 第六步）。

停止條件，任一成立即停：

1. 空格清單填完，或剩餘格已被明確跳過。
2. 連續兩輪重述，專家只說「對」，沒有新增或修正。
3. 約定時間到。到了就停，缺格標 `#待補`，**不拖時間**——拖過承諾的時間，就沒有第二場訪談了。

## 快檢（深度模式必做）

進收斂段前，從判例卡中**保留一張不參與編譯**（挑一張有代表性、非唯一來源的——它承載的判準必須另有卡片支撐，抽走不會讓該判準消失）。編譯完成後拿它問專家：

> 照這份 skill，新人遇到這個情境會怎麼判？

專家說「會判錯」的地方，就是還沒萃取到的判準——回頭補那一條，補完在 coverage 區記「已快檢（判例 #k）」。

**不可拿已編入的判例當快檢。** 用訓練素材驗證自己，背案例也能過關——那驗的是答案，不是思考。

## 中斷續跑

任何中斷後，從私有 checkpoint（台帳＋判例卡＋空格清單狀態）接續。重啟開場改為：

> 上次我們收到了（一句摘要），接下來從（下一個未填格）繼續。

**不重問已答的。** 專家被要求重講一次，會直接拒絕整個專案。
